# Loft Studio · клиентский прототип

Первый этап LOFT BOOKING: адаптивный сайт одной лофт-студии с полным демонстрационным сценарием бронирования. Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, Vitest 5.

## Запуск

Рекомендуется Node.js 24 LTS и npm. Секреты, переменные окружения, база данных и внешние сервисы не нужны.

Все обязательные программные компоненты бесплатны. Будущее размещение планируется на собственном VPS пользователя с Ubuntu 24.04; внешний хостинг, платные подписки и API не требуются. Постоянные правила разработки, GitHub и бюджета закреплены в `AGENTS.md`.

```bash
npm ci
npm run dev
```

Dev-сервер слушает порт 3000. Для production-сборки:

```bash
npm run build
npm start
```

Если порт занят, используйте `npm run dev -- --port 3001` или `npm start -- --port 3001`.

## Проверки

```bash
npm test              # Vitest: доступность, даты, телефоны, валидация, повторная проверка
npm run typecheck     # TypeScript
npm run lint          # ESLint
npm run test:e2e      # Chromium: компьютер 1440px и телефон 390px
npm run capture:acceptance # Семь скриншотов и проверка слотов; нужен запущенный сервер
```

Браузерные тесты запускают dev-сервер автоматически либо используют уже запущенный на порту 3000 (кроме CI). В этой облачной среде Chromium установлен в `/usr/bin/chromium`. На другом компьютере установите браузер через `npx playwright install chromium` и задайте `CHROMIUM_PATH` — абсолютный путь к установленному исполняемому файлу. Без системного Chromium можно убрать `executablePath` в `playwright.config.ts`, чтобы Playwright использовал свой установленный браузер.

[Материалы визуальной приёмки](docs/ACCEPTANCE.md) содержат семь скриншотов, результаты повторной проверки и вопросы для согласования. Для повторного создания снимков запустите `npm run capture:acceptance` в Node.js 24 при работающем приложении; снимки сохраняются в `docs/acceptance/`. Необязательная переменная `ACCEPTANCE_BASE_URL` позволяет указать другой внутренний адрес тестового сервера. Встроенного интерактивного Preview в доступных инструментах текущей среды нет; внешнее размещение для приёмки не требуется.

Для TypeScript закреплена стабильная версия **6.0.3**: текущий `typescript-eslint` пока не поддерживает TypeScript 7. ESLint закреплён на **9.39.5**, совместимой с плагинами `eslint-config-next`; переход на ESLint 10 требует обновления их peer dependencies. Next.js, React, Tailwind и Vitest установлены в актуальных стабильных версиях на момент разработки. Точные версии зависимостей зафиксированы в `package-lock.json`; для повторной установки используйте `npm ci`.

## Реализовано

- Тёплый светлый адаптивный интерфейс, главная иллюстрация, галерея из четырёх изображений с просмотром, описание, временный адрес и правила.
- Календарь в `Europe/Moscow`, запрет прошедших дат и времени, доступность на три календарных месяца вперёд.
- Все **32 получасовых слота** от 07:00 до 22:30; занятые зачёркнуты и отключены.
- Начало предлагается только при наличии непрерывного свободного часа. Окончание автоматически через час, дальнейшее увеличение по 30 минут до следующей брони или 23:00.
- Пересечения запрещены; соседние бронирования разрешены. Доступность повторно читается и проверяется при подтверждении.
- Имя, фамилия, российский мобильный телефон, вид события, Telegram/SMS, обязательное согласие. Телефон нормализуется в `+79XXXXXXXXX`.
- Отдельный демонстрационный экран с датой, временем, продолжительностью, каналом уведомления и явным сообщением, что бронь фактически не сохранена.
- Подписи полей, клавиатурное управление, диалог галереи с Escape, управление фокусом при ошибках и подтверждении, учёт `prefers-reduced-motion`.

## Правила календаря

Окно записи — от сегодняшней московской даты **до даты +3 календарных месяца включительно**. Например, 18 октября → 18 января. Поэтому навигация затрагивает текущий и три последующих месяца; дни за пределами окна отключены. Если соответствующего дня в последнем месяце нет, граница переносится на его последний день.

Интервалы полуоткрытые: `[начало, окончание)`. Бронирование до 18:00 совместимо с бронью с 18:00. Слот 22:30 отображается, но не может быть началом минимальной часовой аренды. Ограничения по заблаговременности нет: ровно наступивший интервал допустим, прошедший — уже нет. Часы обновляются в открытой странице каждые 15 секунд, при подтверждении используется текущее время независимо от таймера.

## Тестовые данные

Шесть вымышленных сценариев повторяются по дням, начиная с сегодняшней московской даты:

| Смещение дня | Сценарий | Занятое время |
|---|---|---|
| Сегодня | Свободный | — |
| +1 | Частично занят | 12:00–14:00, 18:00–20:00 |
| +2 | Бронирования подряд | 10:00–12:00, 12:00–14:00, 14:00–16:00 |
| +3 | Занято утро | 07:00–12:00 |
| +4 | Занят вечер | 17:00–23:00 |
| +5 | Полностью занят | 07:00–23:00 |

Под календарём есть раскрываемый блок «Тестовые сценарии доступности» для быстрого перехода. Если сегодня уже поздно, выберите свободный день через шесть дней. При перезагрузке данные строятся заново; подтверждение не создаёт новую бронь.

## Структура

```text
src/app/                     # Страница, метаданные, стили
src/components/              # Галерея, календарь, выбор времени, форма, подтверждение
src/lib/studio.ts            # Тексты, рабочие часы, ссылки на фото
src/lib/availability.ts      # Московские даты, слоты, границы, конфликты
src/lib/demo-bookings.ts     # Вымышленные бронирования
src/lib/validation.ts        # Валидация формы и нормализация телефона
src/lib/booking-service.ts   # Граница между UI и будущим серверным API
src/lib/*.test.ts            # Модульные тесты
e2e/booking.spec.ts          # Браузерные сценарии
public/images/               # Четыре временные SVG-иллюстрации
docs/IMPLEMENTATION.md       # Отчёт и результаты проверок
```

`BookingService` отделяет чтение доступности и подтверждение от интерфейса. На следующем этапе его можно заменить HTTP-клиентом. Реальное сохранение и атомарная защита от одновременного бронирования должны выполняться сервером с PostgreSQL. Сейчас API, БД и хранение контактных данных отсутствуют; данные формы живут только в памяти вкладки и очищаются после подтверждения.

## Что требуется перед реальным запуском

1. Добавить **четыре оригинальные фотографии заказчика**, обновить пути и alt-тексты в `src/lib/studio.ts`, удалить пометки о заглушках на странице. Сейчас изображения — иллюстрации, а не фотографии студии.
2. Уточнить настоящий адрес, описание, правила аренды и окончательный текст подтверждения. Адрес и правила явно обозначены как временные.
3. В отдельно согласованном следующем этапе реализовать сервер, БД и уведомления. Текущая версия не резервирует студию и не отправляет сообщения.

Административная панель, авторизация, платежи, аналитика, CMS и промышленное развёртывание в первый этап не входят.
