# studio 19.25 · Творческое пространство · DEMO 1.4 / backend 2.1

Пять экранов одного React/Next.js приложения: Welcome → Calendar → Time → Contacts → Confirmation. На странице смонтирован только текущий экран. Серверная основа 2.1 подготовлена от `main` (`06dea2426dd421a0aa8c2b398aaf19518b841fa1`) в отдельной ветке `feat/backend-foundation-v2.1`. Публикация согласованных изменений после merge в `main` выполняется существующим GitHub Actions workflow.

Welcome занимает доступную высоту экрана; галерея и прежние условия аренды открываются кнопкой «О пространстве». Дата переводит на сетку автоматически. «Назад» сохраняет дату, время и контакты; другая дата очищает время. «Новое бронирование» и перезагрузка возвращают Welcome, очищая вымышленные контакты. Состояние хранится только в памяти React.

В общей шапке всех пяти экранов используется оригинальный логотип владельца `public/images/studio-19-25-logo.jpg`, без перерисовки или преобразования файла. Название, подзаголовок, путь логотипа и рабочие часы заданы в `src/lib/studio.ts`. Диапазон аренды — **09:00–23:00**, шаг 30 минут, минимум час; последний допустимый старт — **22:00**. Контактная форма содержит только имя, фамилию и телефон. Нейтральные серые и мягкие коралловые акценты дополняют прежнюю тёплую светлую основу.

## Запуск

Используйте Node.js 24 LTS и npm. Для DEMO секреты, переменные окружения, база данных и внешние сервисы не нужны.

Все обязательные программные компоненты бесплатны. Будущее размещение планируется на собственном VPS пользователя с Ubuntu 24.04; внешний хостинг, платные подписки и API не требуются. Постоянные правила разработки, GitHub и бюджета закреплены в `AGENTS.md`.

```bash
npm ci
npm run dev
```

Dev-сервер слушает порт 3000. Для production-сборки:

```bash
npm run build
npm start
```

Если порт занят, используйте `npm run dev -- --port 3001` или `npm start -- --port 3001`.

## Локальный SERVER 2.1

PostgreSQL запускается бесплатно в Docker Compose; интерфейс DEMO и GitHub Pages не требуют его наличия. Команды ниже создают только локальные секреты (игнорируются Git), БД и служебный журнал миграций:

```bash
npm ci
npm run db:env
npm run db:up
npm run db:check
npm run db:migrate
npm run dev:server
```

Проверка в другом терминале: `curl -i http://127.0.0.1:3000/api/health` (200 при доступной БД, 503 при отказе). Оптимизированный SERVER: `npm run build:server`, затем `npm run start:server`. Штатная остановка БД: `npm run db:stop`, без удаления volume. Серверный экран пока не позволяет начинать запись; демонстрационная занятость не используется как реальная база.

Режим выбирается командами явно через `APP_MODE`, а не наличием строки подключения. `dev/build/start` — DEMO Node; `build:demo` — статический DEMO; команды с `:server` — SERVER. Инструкции для отдельной тестовой базы, интеграционных и HTTP-тестов — [backend-local-setup.md](docs/backend-local-setup.md). Применённые SQL-файлы не редактировать. Производственных секретов, бронирований и VPS-развёртывания в 2.1 нет.

## Реализовано

- Тёплый светлый адаптивный интерфейс. Welcome содержит прежнюю главную иллюстрацию и тексты; галерея из четырёх изображений, описание, временный адрес и правила доступны в диалоге «О пространстве».
- Календарь в `Europe/Moscow`, запрет прошедших дат и времени, доступность на три календарных месяца вперёд.
- Все **28 получасовых слотов** от 09:00 до 22:30; занятые зачёркнуты и отключены.
- Первое нажатие в сетке выбирает час. Нажатия справа и слева расширяют непрерывный интервал, включая промежуточные слоты. Расширение через занятую границу запрещено. Выпадающих списков времени нет.
- Нажатие выбранного слота сокращает окончание так, чтобы нажатый слот остался последним включённым. Минимум — час. Нажатие первого слота или «Сбросить выбор» очищает интервал. Повторное нажатие последнего слота не меняет выбор. Смена даты сбрасывает время.
- Под сеткой показана легенда «Свободно · Занято · Выбрано», итоговый интервал и продолжительность. Выбор обозначен цветом и `aria-pressed`.
- Пересечения запрещены; соседние бронирования разрешены. Доступность повторно читается и проверяется при подтверждении.
- После выбора даты показывается отдельный экран сетки. После кнопки «Продолжить» открывается отдельный экран формы: имя, фамилия, мобильный телефон. Поля мероприятия нет. Телефон нормализуется в `+79XXXXXXXXX`. Чекбокса согласия и выбора уведомлений в демонстрационном интерфейсе нет.
- Экран «Ваше бронирование»: дата, время, продолжительность, имя и фамилия, нормализованный телефон и предупреждение «Это демонстрация. Бронирование не создаётся, данные не сохраняются и уведомления не отправляются». «Новое бронирование» очищает выбор и контактные данные.
- Контакт администратора доступен на главной, в выборе времени, форме и итоговом экране. Единственная настройка — `STUDIO.adminPhone` в `src/lib/studio.ts`. Сейчас она `null`, поэтому выводится заглушка. При корректно указанном номере компонент создаёт `tel:`-ссылку.
- Подписи полей, клавиатурное управление, диалог галереи с Escape, управление фокусом при ошибках и подтверждении, учёт `prefers-reduced-motion`.

## Правила календаря

Окно записи — от сегодняшней московской даты **до даты +3 календарных месяца включительно**. Например, 18 октября → 18 января. Поэтому навигация затрагивает текущий и три последующих месяца; дни за пределами окна отключены. Если соответствующего дня в последнем месяце нет, граница переносится на его последний день.

Интервалы полуоткрытые: `[начало, окончание)`. Бронирование до 18:00 совместимо с бронью с 18:00. Слот 22:30 отображается, но не может быть началом минимальной часовой аренды. Ограничения по заблаговременности нет: ровно наступивший интервал допустим, прошедший — уже нет. Часы обновляются в открытой странице каждые 15 секунд, при подтверждении используется текущее время независимо от таймера.

## Тестовые данные

Шесть вымышленных сценариев повторяются по дням, начиная с сегодняшней московской даты:

| Смещение дня | Сценарий | Занятое время |
|---|---|---|
| Сегодня | Свободный | — |
| +1 | Частично занят | 12:00–14:00, 18:00–20:00 |
| +2 | Бронирования подряд | 10:00–12:00, 12:00–14:00, 14:00–16:00 |
| +3 | Занято утро | 09:00–12:00 |
| +4 | Занят вечер | 17:00–23:00 |
| +5 | Полностью занят | 09:00–23:00 |

Переключателей тестовых сценариев в клиентском интерфейсе нет. Сценарии доступны тестам через существующий источник данных; браузерные тесты выбирают нужную дату обычным календарём. Если сегодня уже поздно, выберите свободный день через шесть дней. При перезагрузке данные строятся заново; подтверждение не создаёт новую бронь.

## Структура

```text
src/app/                     # Страница, метаданные, стили
src/components/              # Welcome/описание, календарь, сетка, форма, подтверждение
src/lib/studio.ts            # Тексты, рабочие часы, ссылки на фото
src/lib/availability.ts      # Московские даты, слоты, границы, конфликты
src/lib/selection.ts         # Непрерывный выбор, расширение, сокращение, сброс
src/lib/admin-contact.ts     # Проверка настройки контакта администратора
src/lib/demo-bookings.ts     # Вымышленные бронирования
src/lib/validation.ts        # Валидация формы и нормализация телефона
src/lib/booking-service.ts   # Граница между UI и будущим серверным API
src/lib/*.test.ts            # Модульные тесты
e2e/                        # Бронирование, сетка, повторный конфликт, общие шаги
scripts/capture-acceptance.mjs # Пять экранов на компьютере и телефоне
public/images/               # Четыре временные SVG-иллюстрации
docs/acceptance/v1.4/        # Пять экранов, адаптивность и результаты
```

`BookingService` отделяет чтение доступности и подтверждение от интерфейса. На следующем этапе его можно заменить HTTP-клиентом. Реальное сохранение и атомарная защита от одновременного бронирования должны выполняться сервером и БД; для следующих этапов утверждены Next.js Route Handlers и PostgreSQL. В SERVER 2.1 реализован только health endpoint и инфраструктура БД; операций бронирования и хранения контактов нет. В DEMO базы и API нет. Введённые вымышленные данные остаются в памяти вкладки для итогового экрана и очищаются при новом бронировании, перезагрузке или закрытии страницы. В `localStorage`, `sessionStorage`, cookies или на сервер они не записываются.

## Демонстрационные данные и правовые ограничения

Используйте только вымышленные контакты. Реальные персональные данные на этом этапе не собираются. Автозаполнение контактных полей отключено; предупреждение показано перед формой.

Отсутствие чекбокса в демоверсии не означает, что согласие получено, и не является готовым юридическим решением. Перед обработкой реальных персональных данных нужно определить правовое основание обработки, обязательные уведомления и применимые требования законодательства; при необходимости добавить соответствующий текст или отдельное согласие. Код не подставляет скрытое согласие автоматически.

Тип `NotificationChannel`, список `CHANNELS` и необязательные предпочтения сохранены в архитектуре для будущей реализации Telegram/SMS. В интерфейсе они скрыты, выбор не требуется, реальные сообщения не отправляются.

## Что требуется перед реальным запуском

1. Добавить **четыре оригинальные фотографии заказчика**, обновить пути и alt-тексты в `src/lib/studio.ts`, удалить пометки о заглушках на странице. Сейчас изображения — иллюстрации, а не фотографии студии.
2. Уточнить настоящий адрес, описание, правила аренды, номер администратора и окончательные маркетинговые тексты. Адрес и правила явно обозначены как временные, номер не придуман.
3. В отдельно согласованном следующем этапе добавить к подготовленной серверной основе операции бронирования; уведомления согласовать отдельно. Текущая версия не резервирует студию и не отправляет сообщения.
4. Согласовать правовые основания и тексты до обработки реальных контактов.

Административная панель, авторизация, платежи, аналитика, CMS и промышленное развёртывание в первый этап не входят.
