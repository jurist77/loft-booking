# Постоянные правила Loft Booking

- Работать в текущем проекте; сохранять работающие модули и историю изменений. Не создавать приложение заново.
- Использовать существующий GitHub-репозиторий `jurist77/loft-booking`. После завершения и согласования этапа фиксировать изменения коммитом и отправлять в GitHub. Для существенных доработок использовать отдельные ветки, когда это целесообразно.
- Не выполнять force push и другую принудительную перезапись истории. Без разрешения не создавать новый репозиторий. При отсутствии доступа сообщать, какое действие требуется от пользователя.
- Проверять состав каждого коммита: не включать секреты, токены, пароли, реальные контактные данные, `.env`, зависимости и результаты сборки. Тестовые примеры из ТЗ должны оставаться явно вымышленными.
- Использовать бесплатные программные компоненты и сервисы. Не подключать платные API, подписки и функции без отдельного согласования. Если бесплатная реализация невозможна, заранее объяснить ограничение и предложить альтернативу.
- Будущее размещение — собственный VPS пользователя на Ubuntu 24.04. Внешний хостинг не является обязательной зависимостью и не нужен только ради визуальной приёмки.
- Первый этап ограничен клиентским прототипом. Не начинать второй этап, не подключать серверную инфраструктуру, БД, реальные уведомления или оплату и не выполнять внешнее развёртывание до отдельного разрешения.
- Для приёмки использовать доступный встроенный Preview, а при его отсутствии — настоящие скриншоты браузерных проверок. Не выдавать внутренний адрес облачной машины за доступную пользователю ссылку.
