# Локальный запуск backend 2.1

Инструкция рассчитана на локальную разработку и тесты. Настоящие контакты не вводить. VPS и публичную базу на этом этапе настраивать не нужно.

## Что установить

- Git, **Node.js 24 LTS**, npm. Серверные CLI используют встроенный запуск TypeScript Node 24; дополнительный компилятор не нужен.
- Бесплатный Docker Engine с Compose plugin на Linux либо Docker Desktop, если его условия бесплатного использования подходят вашему компьютеру. Docker должен быть запущен.
- Для E2E — Chromium/Playwright, как описано в [README](../README.md).

Проверка инструментов:

```bash
node --version
npm --version
docker info
docker compose version
```

Не публикуйте вывод команд окружения, содержимое `.env` или полные логи с реквизитами подключения.

## Первый запуск

Откройте терминал в папке существующего репозитория `loft-booking`. Не создавайте новый проект.

```bash
npm ci
npm run db:env
npm run db:up
npm run db:status
npm run db:check
npm run db:migrate
npm run db:migrate
```

`db:env` создаёт **два разных** игнорируемых файла: `.env.local` для разработки и `.env.test.local` для тестов. Пароли генерируются случайно, не печатаются; существующие файлы сохраняются без изменений. Не отправляйте их в GitHub или чат. `.env.example` — только справочник параметров, с пустыми секретами. Для обычного запуска вручную заполнять его не нужно.

Первый `db:up` скачивает официальный `postgres:17-alpine`, создаёт контейнер, роли и именованный volume. Дождитесь состояния `healthy`. PostgreSQL доступен с этого компьютера по `127.0.0.1:54329`, не из интернета. `db:check` должен вывести `PostgreSQL connection: ready`. Первый запуск миграций применяет одну версию, повторный — **0 новых миграций**. В базе создаётся только служебная таблица `studio.schema_migrations`.

Далее запустите Next.js в SERVER-режиме:

```bash
npm run dev:server
```

Оставьте этот терминал открытым. В браузере откройте `http://127.0.0.1:3000/`. Увидите студию и сообщение, что онлайн-запись пока недоступна. Серверный режим ещё не предлагает реальные или демонстрационные бронирования.

В другом терминале:

```bash
curl -i http://127.0.0.1:3000/api/health
```

Норма: **HTTP 200**, `{"status":"ok"}`. Параметры БД в ответе отсутствуют. Для проверки оптимизированной Node-сборки остановите dev через Ctrl+C, затем:

```bash
npm run build:server
npm run start:server
```

Для другого порта добавьте `-- --port 3001` к `dev:server` или `start:server`. По умолчанию приложение слушает только `127.0.0.1`; настройки публичного доступа относятся к будущему VPS-этапу.

## Проверка отказа и повторный запуск

Пока Next.js работает, в другом терминале:

```bash
npm run db:stop
curl -i http://127.0.0.1:3000/api/health
npm run db:up
npm run db:check
npm run db:migrate
curl -i http://127.0.0.1:3000/api/health
```

При остановленной БД ожидается **503** и `{"status":"unavailable"}`, после запуска — **200**. Volume и журнал миграций сохраняются, повторное применение не дублируется. Штатная остановка — `npm run db:stop`; Next.js останавливается Ctrl+C. **Не используйте `docker compose down -v` для обычной остановки:** этот параметр удаляет данные.

## Тестовая база и проверки

Тесты имеют отдельную базу `studio1925_test`, роли, пароли, volume и порт `127.0.0.1:54330`. Не подменяйте её рабочей базой. Интеграционные тесты намеренно очищают только служебный журнал в этой изолированной тестовой базе; они откажутся запускаться на базе без суффикса `_test`, внешнем адресе или при наличии посторонних таблиц в схеме `studio`.

```bash
npm test
npm run typecheck
npm run lint
npm run build:server
npm run db:test:up
npm run db:test:check
npm run test:integration
npm run test:server:http
npm run db:test:stop
```

`test:integration` использует настоящий PostgreSQL. `test:server:http` запускает собственный собранный Next.js на порту **3011**, проверяет HTTP 200, останавливает только тестовую БД, проверяет 503 и запускает её снова. После проверки сервер завершается. Порт 3011 должен быть свободен. Отказ проверки нельзя считать успешным тестом.

Клиентские проверки и независимость DEMO:

```bash
npm run build
npm run test:e2e
npm run test:demo:isolation
npm run preview:demo
```

`test:e2e` автоматически поднимает DEMO dev-сервер, если порт 3000 свободен. Сначала остановите SERVER на этом порту. `test:demo:isolation` собирает статический DEMO с недоступным адресом БД и случайными секретами-маркерами, затем проверяет их отсутствие в экспорте и отсутствие серверного API. Для проверки экспорта в другом терминале:

```bash
PLAYWRIGHT_BASE_URL=http://127.0.0.1:4173/loft-booking/ npm run test:e2e
```

Команды DEMO принудительно выбирают режим `demo`, даже если `.env.local` содержит SERVER-настройки. PostgreSQL для них не нужен. Для локального DEMO без Docker достаточно `npm ci` и `npm run dev`. Не запускайте одновременно разные сборки, использующие `.next`; SERVER использует отдельный `.next-server`.

## Миграции

Команда `npm run db:migrate` использует **MIGRATION_DATABASE_URL**, приложение — **DATABASE_URL**. Это разные роли: приложение не superuser и не может менять схему/журнал. Тестовые аналоги: `db:test:migrate`, `db:test:check`.

Новые SQL-файлы добавляются последовательно (`0002_имя.sql` с латинскими буквами в имени); применённые файлы не редактировать. Нельзя добавлять в них собственные BEGIN/COMMIT/ROLLBACK или SQL, несовместимый с транзакцией. Подробнее — [migrations/README.md](../migrations/README.md).

Если процесс миграции завершился ошибкой, команда возвращает ненулевой код, а не успех. `HISTORY_MISMATCH` означает расхождение с применёнными файлами; восстановите оригинальные файлы из Git и выясните причину. Не исправляйте вручную checksum и не удаляйте журнал. `MIGRATION_LOCKED` означает, что другой процесс уже выполняет миграции: дождитесь его завершения и повторите команду. `MIGRATION_FAILED` требует проверки конфигурации/доступности и SQL-кода; секреты в отчёт не копировать.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `Docker ... unavailable` / нет daemon | Запущен ли Docker; работает ли `docker info`; есть ли у пользователя штатный доступ к Docker. Не открывать сетевой Docker socket. |
| Ошибка скачивания образа | Интернет/доступ к Docker Hub; не менять VPN или другие проекты. Повторить `db:up` после восстановления сети. |
| Контейнер не `healthy` | `db:status`, наличие локального env-файла; доступность порта; права чтения `docker/postgres/init-roles.sh` (0644). Диагностические логи просматривать локально, не публиковать с секретами. |
| Порт занят | Для dev поменять `POSTGRES_PORT` и порт в обеих dev URL в `.env.local`; для тестов — соответствующие три значения `.env.test.local`. Сохранить привязку 127.0.0.1. Перезапустить свой Compose project. |
| После смены пароля соединение не работает | Init выполняется только на пустом volume. Файл окружения не меняет уже созданную роль. Вернуть прежние локальные настройки либо отдельно согласовать смену пароля; volume не удалять автоматически. |
| SERVER health 503 | `db:status`, затем `db:check`; совпадают ли база/пользователь/пароль/порт с локальным env. Не использовать bootstrap-роль вместо приложения. |
| `/api/health` отвечает 404 | Проверить, что запущен `dev:server` / `start:server`, а не DEMO. На Pages endpoint отсутствует по замыслу. |
| TypeScript CLI не запускается | Проверить Node.js 24 и повторить `npm ci`. |
| E2E видит отключённую запись | На порту 3000 остался SERVER. Остановить его, запустить DEMO или указать URL статического preview. |

Дампы и локальные персональные данные не хранить в отслеживаемых файлах; для временных файлов игнорируются `db-dumps/` и `local-data/`. Никаких реальных контактов для этих проверок не требуется.
