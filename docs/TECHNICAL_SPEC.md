# LOFT BOOKING
## Техническое задание №1 — разработка клиентского веб-приложения

**Версия:** 1.0  
**Этап:** 1 — клиентский интерфейс  
**Статус:** к разработке

### 1. Цель

Создать работающий прототип веб-сервиса бронирования одной лофт-студии.

Клиент открывает сайт по ссылке, знакомится со студией, выбирает дату и свободное время, заполняет контактную форму и получает демонстрационное подтверждение.

На первом этапе используем тестовые бронирования. Реальная база данных, административная панель и отправка уведомлений будут реализованы позже.

### 2. Технологии

- Next.js (App Router)
- React
- TypeScript
- Tailwind CSS
- Vitest для тестирования
- GitHub для хранения кода

Приложение должно корректно работать на смартфонах и компьютерах. Основной приоритет — мобильный интерфейс.

Использовать актуальные стабильные версии библиотек.

### 3. Главная страница

Создать одностраничный сайт со следующими разделами:

1. Название студии — временно «Loft Studio».
2. Главное фото.
3. Галерея фотографий.
4. Краткое описание студии.
5. Адрес и правила аренды — временный текст.
6. Кнопка «Забронировать».
7. Календарь и форма бронирования.

**Фотографии:** использовать четыре реальные фотографии, предоставленные заказчиком. Если они отсутствуют в рабочей среде Codex, использовать временные заглушки и явно указать необходимость добавления оригиналов.

Дизайн: светлый, тёплый, бежевые оттенки, элементы древесного и тёмно-зелёного цветов.

Фотографии, тексты и рабочие часы пока изменяются разработчиком непосредственно в исходном коде. Не создавать для них административный интерфейс, CMS или отдельную систему настроек.

### 4. Календарь

- Часовой пояс: `Europe/Moscow`.
- Рабочее время: 07:00–23:00.
- Шаг бронирования: 30 минут.
- Минимальная аренда: 60 минут.
- Максимальная продолжительность: до конца рабочего дня при наличии свободного времени.
- Запись доступна на три календарных месяца вперёд.
- Запрещён выбор прошедших дат и времени.
- Бронирование возможно без дополнительного ограничения по времени до начала.

Клиент выбирает месяц, затем дату.

После выбора даты показывать **все 32 получасовых слота** с 07:00 до 22:30.

Занятые слоты должны отображаться зачёркнутыми и быть недоступными для выбора.

### 5. Логика выбора времени

**5.1. Начало аренды**

Предусмотреть выпадающий список доступного времени начала.

В списке отображать только интервалы, после которых имеется минимум 60 минут непрерывного свободного времени.

Занятые и недопустимые интервалы в выпадающий список не включать.

**5.2. Автоматическое окончание**

После выбора времени начала автоматически устанавливать время окончания на 60 минут позже.

Пример: 16:30 → 17:30.

**5.3. Изменение окончания**

Предусмотреть выпадающий список времени окончания.

Клиент может увеличивать продолжительность аренды с шагом 30 минут.

В списке показывать только допустимые варианты, не пересекающиеся с существующими бронированиями.

Пример: если студия занята с 18:00 до 20:00, при выборе начала 16:00 допустимы окончания 17:00, 17:30 и 18:00.

**5.4. Проверка конфликтов**

Не допускать пересечения бронирований.

Допускать соседние бронирования, например 16:00–17:00 и 17:00–18:00.

При попытке подтверждения повторно проверять доступность интервала.

Если интервал занят, выводить сообщение об ошибке и предлагать выбрать другое время.

### 6. Контактная форма

Обязательные поля:

- Имя.
- Фамилия.
- Телефон.
- Вид мероприятия.
- Канал уведомления.
- Согласие на обработку персональных данных.

Виды мероприятий:
- День рождения.
- Аренда студии.
- Другое.

Каналы уведомлений:
- Telegram.
- SMS.

В первой версии реальная отправка уведомлений не выполняется.

### 7. Нормализация телефона

Разрешить ввод российского мобильного номера в различных форматах:

| Ввод | Результат |
|---|---|
| 89261234567 | +79261234567 |
| +79261234567 | +79261234567 |
| 79261234567 | +79261234567 |
| 9261234567 | +79261234567 |
| 8 (926) 123-45-67 | +79261234567 |

Удалять пробелы, дефисы и скобки, корректно обрабатывать префиксы 7 и 8.

Проверять, что после нормализации получен российский мобильный номер формата `+79XXXXXXXXX`.

При неполном или некорректном вводе показывать понятную ошибку.

### 8. Экран подтверждения

После успешной проверки формы показывать отдельный демонстрационный экран с:

- Датой бронирования.
- Временем начала и окончания.
- Продолжительностью аренды.
- Выбранным каналом уведомления.

Окончательный текст экрана подтверждения будет согласован позднее.

Обязательно обозначить, что бронирование демонстрационное и фактически не сохранено.

### 9. Демонстрационные бронирования

Создать тестовые данные для проверки разных сценариев:

- Свободный день.
- Частично занятый день.
- Несколько бронирований подряд.
- Занятое время утром.
- Занятое время вечером.
- Полностью занятый день.

Все данные должны быть вымышленными.

### 10. Требования к архитектуре

Разделить код на компоненты интерфейса, расчёт доступности, проверку формы и работу с тестовыми бронированиями.

Рабочее время, фотографии и тексты можно хранить в обычных исходных файлах проекта. Изменять их в дальнейшем будем через Codex.

Не создавать интерфейс редактирования этих параметров.

Предусмотреть возможность последующего подключения PostgreSQL и серверного API без полной переработки клиентского интерфейса.

### 11. Тестирование

Создать автоматические тесты:

1. Минимальная аренда 60 минут.
2. Автоматическое окончание через час.
3. Исключение занятых интервалов из выпадающих списков.
4. Запрет пересечения бронирований.
5. Разрешение соседних бронирований.
6. Запрет времени в прошлом.
7. Проверка окончания рабочего дня.
8. Корректность выбора даты в часовом поясе Москвы.
9. Нормализация телефона во всех указанных форматах.
10. Корректная обработка ошибочных данных.

### 12. Критерии приёмки

Приложение должно:

- Запускаться локально без ошибок.
- Корректно отображаться на телефоне и компьютере.
- Показывать календарь на три месяца вперёд.
- Отображать все временные слоты, зачёркивая занятые.
- Не показывать занятые интервалы в выпадающих списках.
- Автоматически устанавливать окончание через 60 минут.
- Не допускать конфликтующих бронирований.
- Проверять и нормализовать телефон.
- Позволять пройти полный демонстрационный путь бронирования.
- Успешно проходить автоматические тесты.
