# Отчёт: LOFT BOOKING, этап 1

Дата проверки: 18 октября 2026 года. Основание: [ТЗ №1](./TECHNICAL_SPEC.md).

Реализован работающий клиентский прототип одной студии. Полный путь: знакомство с пространством → выбор московской даты → свободное время → контактные данные → отдельное демонстрационное подтверждение.

## Выполненные требования

| Область | Результат |
|---|---|
| Стек | Next.js 16.4.2, React 19.3.1, TypeScript 6.0.3, Tailwind CSS 4.3.3, Vitest 5.0.5; npm lockfile |
| Главная | Название, главное изображение, галерея из четырёх временных иллюстраций, описание, предварительные адрес и правила, переход к бронированию |
| Галерея | Диалог просмотра, переключение четырёх изображений, закрытие по Escape, кнопке и фону |
| Адаптивность | Телефон и компьютер; поля с мобильной клавиатурой, увеличенные сенсорные кнопки времени |
| Даты | `Europe/Moscow`, сегодня → +3 календарных месяца включительно, запрет прошедших дат |
| Время | 07:00–23:00, 32 видимых слота, шаг 30 минут, минимальная аренда 60 минут |
| Начало и конец | Только допустимые начала; автоматический конец +60 минут; продление до следующей брони или закрытия |
| Конфликты | Пересечения запрещены, соседние интервалы разрешены, повторное чтение доступности при подтверждении |
| Форма | Все шесть обязательных данных, три вида событий, Telegram/SMS, согласие и сообщения об ошибках |
| Телефон | Все пять форматов из ТЗ приводятся к `+79XXXXXXXXX`, неправильные номера отклоняются |
| Подтверждение | Дата, начало, окончание, продолжительность, выбранный канал, явное предупреждение о демонстрации |
| Тестовые брони | Шесть повторяющихся вымышленных сценариев и быстрые переходы под календарём |
| Архитектура | Отдельные компоненты, функции доступности и валидации, источник тестовых данных, интерфейс `BookingService` для будущего API |

Рабочее время, тексты и пути к фотографиям находятся в исходном коде. CMS и интерфейса настроек нет.

## Результаты проверок

Проверки выполнены в облачной среде с Node.js 24.19.0, npm 11.9.0 и системным Chromium 154.

| Команда / проверка | Итог |
|---|---|
| `npm ci` | Повторная установка из lockfile успешна |
| `npm run lint` | Успешно, без ошибок и предупреждений линтера |
| `npm run typecheck` | Успешно |
| `npm test` | **62 из 62**, 3 тестовых файла |
| `npm run build` | Production-сборка успешна |
| `npm start` + HTTP-запрос | Успешный запуск, главная возвращает HTTP 200 и ожидаемое содержимое |
| `npm run test:e2e` | **8 из 8** на production-сборке: по 4 сценария на 1440×1000 и 390×844, включая конфликт при подтверждении |
| `npm run capture:acceptance` | Семь браузерных скриншотов; проверены 32 слота, зачёркивание занятых, автоматический конец и варианты продления |
| Дополнительная адаптивная проверка | 320, 360, 390, 768, 1024, 1440 px: без горизонтального переполнения, изображения загружаются |

Модульные тесты проверяют минимальный час, автоматический конец, свободные списки, конфликты и соседство, прошедшее время с точностью до секунды, конец рабочего дня, московскую смену даты, трёхмесячную границу и короткие месяцы, все форматы телефонов и ошибочные данные. Сервис проверен на появление конфликта **после первоначальной загрузки** доступности.

Браузерные сценарии проверяют галерею, все 32 слота, отключённые занятые интервалы, автоматический конец и предел продления, форму, обязательное согласие, неверный телефон, полностью занятый день, переходы месяцев, подтверждение и очистку контактов после возврата. В полном сценарии проверяется отсутствие клиентских исключений и ошибок консоли.

Повторная приёмка включает реальную ветку ошибки конфликта в браузере: тест выбирает свободный будущий день, затем управляемыми часами сдвигает начало демонстрационных данных на сутки. Повторная проверка сервиса видит занятой интервал, интерфейс показывает ошибку и не переходит к подтверждению. Текст ошибки не подставляется в DOM вручную. Подробности и снимки: [визуальная приёмка](ACCEPTANCE.md).

## Известные ограничения и согласованные допущения

- **Оригинальные фотографии не предоставлены.** Четыре локальные SVG-иллюстрации помечены как временные; их необходимо заменить фотографиями заказчика. Это не реальные изображения студии.
- Адрес, описание условий аренды и текст подтверждения предварительные; перед запуском требуется согласование.
- Горизонт трактуется как сегодняшняя московская дата плюс три календарных месяца включительно. При отсутствии соответствующего дня используется последний день месяца. Это даёт текущий и до трёх последующих месяцев в навигации.
- Данные вымышленные, повторяются каждые шесть дней и пересчитываются от текущей московской даты. Настоящих броней нет.
- Подтверждение ничего не сохраняет и не резервирует. Контакты не отправляются на сервер и не записываются в браузерное хранилище. SMS и Telegram не отправляются.
- Повторная проверка конфликта реализована через границу сервиса. Атомарная защита от одновременных реальных броней должна появиться вместе с сервером и PostgreSQL.
- Часы интерфейса обновляются раз в 15 секунд; при подтверждении проверка использует фактическое текущее время.
- TypeScript 6.0.3 и ESLint 9.39.5 закреплены для совместимости текущих плагинов Next.js. `typescript-eslint` не поддерживает TypeScript 7; часть ESLint-плагинов ещё не объявляет поддержку ESLint 10. npm сообщает о завершении поддержки ветки ESLint 9. Обновление возможно после появления совместимых версий плагинов.
- Автоматические браузерные проверки выполнены в Chromium; реальные устройства, Safari и Firefox отдельно не проверялись.

PostgreSQL, административная панель, авторизация, реальные уведомления, оплата, аналитика и промышленное развёртывание не реализовывались. Приложение не опубликовано. Следующий этап не начат; результат подготовлен для проверки заказчиком.

Все обязательные компоненты бесплатны. Будущее размещение — собственный VPS пользователя на Ubuntu 24.04; внешний хостинг и платные API не требуются.
