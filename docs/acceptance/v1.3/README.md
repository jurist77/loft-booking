# Визуальная приёмка Loft Booking · ТЗ №1.3

Проверка: 18 октября 2026. Рабочая ветка: `feat/booking-stepper-v1.3`.
База — актуальный `main`, `51a06f26c3b7045371c3d2ea891be5881cbb9e57`.

## Результат

В одном Next.js приложении последовательно показываются Welcome → Calendar → Time → Contacts → Confirmation. Смонтирован только текущий экран: следующих шагов нет ниже страницы или среди скрытых полей. Переходы выполняются React-состоянием без перезагрузки документа, отдельных маршрутов и записи контактов в URL.

- Welcome содержит прежние название, иллюстрацию, описание и кнопку «Забронировать». Используется доступная высота `100dvh`. Остальные прежние тексты, условия и четыре изображения сохранены в диалоге «О пространстве», открываемом по запросу; он не добавляет секции ниже Welcome.
- Calendar показывает только выбор даты; нажатие даты автоматически открывает Time. Кнопка «Назад» возвращает Welcome.
- Time показывает все 32 слота, трёхцветную легенду и прежнюю логику часа, расширения, сокращения и сброса. «Назад» возвращает календарь, «Продолжить» открывает форму только при допустимом интервале.
- Contacts содержит прежнюю форму и сводку выбранного времени. Возврат сохраняет все введённые поля, дату и интервал. Выбор другой даты сбрасывает только время. Повторный выбор той же даты сохраняет интервал.
- Confirmation показывает данные и честное DEMO-предупреждение. «Новое бронирование» очищает состояние и возвращает Welcome. Обновление браузера также начинает с Welcome.

Контакт администратора доступен на всех пяти экранах; номер по-прежнему не предоставлен, используется прежняя заглушка. Фокус переносится на заголовок текущего экрана, при ошибке — на поле/сообщение. Галерея сохраняет Escape и управление фокусом; закрытие описания возвращает фокус на открывшую его кнопку.

Тесты сохраняют старые проверки доступности/конфликтов и добавляют последовательность экранов, отсутствие соседних шагов в DOM, сохранение данных при возврате через Welcome, сброс после нового бронирования/reload и переходы без загрузки нового документа.

Welcome отдельно проверен без вертикальной прокрутки на **320×568, 375×667, 390×844 и 1440×900**. На очень коротком экране **320×300** прокрутка разрешена, кнопки/нижние слоты остаются достижимыми. Для всех экранов также пройден путь на ширинах **320, 360, 375, 390, 430, 768, 1024, 1440 px**: горизонтальной прокрутки нет. На каждом шаге проверено наличие только одного `[data-screen]`.

Старые модульные тесты не удалялись. Браузерные проверки адаптированы к входу через Welcome/Calendar; сохранены проверки клавиатуры, зачёркнутой занятости, минимального часа, расширения в обе стороны, сокращения, смены даты, границы 23:00, окна +3 месяца, повторного конфликта и телефона. Проверка часов браузера подтверждает московскую дату при открытии после статической сборки.

## Безопасность и сохранённые части

Контакты остаются только в оперативной памяти вкладки. Проверки не обнаружили их в localStorage, sessionStorage, cookies, URL или сетевых запросах. Нет POST/PUT и сторонних запросов; JavaScript/консоль без ошибок, ресурсы загружаются успешно. Реальное бронирование и уведомления не создаются. DEMO-предупреждение остаётся перед подтверждением и на итоге. Для проверки используются только вымышленные значения.

Без изменений сохранены `AGENTS.md`, `STUDIO`, SVG-изображения, бизнес-модули `availability`, `selection`, `validation`, `demo-bookings`, `booking-service`, их модульные тесты, зависимости/lockfile и архитектурный документ VPS. Оформление и прежние маркетинговые тексты сохранены; изменена компоновка и навигация. Отдельно исправлено наследование крупного размера заголовка администраторского контакта на мобильном итоге.

## Публикация и ограничения

Публикация из `main` уже работает для предыдущей версии: [run 39131507634](https://github.com/jurist77/loft-booking/actions/runs/39131507634). В этой задаче инфраструктура и условия deployment не менялись; workflow получает только новый путь `docs/acceptance/v1.3/` для артефакта снимков/проверок. После согласованного merge push в `main` автоматически запустит build → deploy → verify-published на существующем адресе **https://jurist77.github.io/loft-booking/**. Приёмка новой версии на публичном адресе выполняется после merge; до этого существующий сайт не является превью ветки 1.3.

Доступного встроенного интерактивного Preview в инструментах чата нет. Новая ветка не публиковалась отдельно, merge не выполнялся. Для визуального согласования сейчас предназначены PR и эти снимки. [Порядок обновления DEMO](../../demo-deployment.md).

Ограничения:

- Проверки выполнялись в Chromium с эмуляцией мобильного экрана; физические Mac/iPhone, Safari и Firefox отдельно не проверялись.
- Только Welcome рассчитан на отсутствие вертикальной прокрутки в стандартном viewport. Другие шаги, короткие окна и увеличенный контент могут прокручиваться; общего запрета прокрутки нет.
- Кнопки «Назад» принадлежат приложению. История браузера не хранит шаги; refresh намеренно удаляет выбор и контакты.
- Оригинальные фотографии, окончательный адрес/тексты и номер администратора остаются на согласование.
- DEMO ничего не сохраняет; до реальной обработки персональных данных требуется отдельное правовое и техническое решение. Хостинг GitHub может вести собственные технические журналы запросов/IP.
- Backend, база данных, админ-панель, SMS, Telegram и VPS-развёртывание не начаты. Платные сервисы и новые зависимости не добавлены.

После предоставления PR ожидается визуальная приёмка. Автоматического слияния не настроено.
