## Публичная публикация пока не подтверждена

Ожидаемый адрес `https://jurist77.github.io/loft-booking/` проверен по HTTPS: **HTTP 404, Site not found · GitHub Pages**. Это ответ площадки, а не рабочая DEMO. Управление Pages и чтение настроек через GitHub API недоступны: прокси возвращает Forbidden для `api.github.com`. Видимость/права Pages достоверно не установлены. Анонимный адрес репозитория также возвращает 404; это не заменяет авторизованную проверку настроек.

Следовательно, критерии публичной публикации и проверки клиентского пути на Pages **ещё не выполнены**. Требуются действия владельца из [инструкции](../../demo-deployment.md#однократные-действия-владельца-github). Не покупать тариф и не менять видимость закрытого репозитория без отдельного решения владельца. После доступа повторить запуск workflow и проверки фактического URL.

## Выполненные изменения

- Добавлен независимый статический target для Pages с конфигурационным basePath и локальными изображениями без серверного оптимизатора. Обычная Node-сборка сохранена.
- Календарь и вымышленная занятость инициализируются при открытии страницы, чтобы дата static build не замораживала календарь. Чистые функции дат и выбора интервалов, московская зона, fixtures и `BookingService` не изменены.
- Добавлены DEMO-баннер и предупреждения перед подтверждением и на итоге. Контакты остаются только в памяти вкладки; сеть/хранилища не используются.
- Добавлены официальные GitHub Actions с минимальными правами, проверкой бесплатного/public сценария, аудитом export и проверкой именно опубликованного сайта после deploy.
- Добавлены конфигурационные/браузерные тесты, проверки восьми ширин, инструкции публикации и архитектурный анализ VPS. Backend не реализован.

## Аудит и ограничения

Исходники и состав экспорта проверены на известные форматы ключей/токенов, приватные ключи и URL со встроенными учётными данными: совпадений не обнаружено. В коммит не включаются `.env`, `node_modules`, `.next`, `out`, тестовые трассы и учётные данные. Настоящих клиентских контактов/номера администратора нет. Это проверка состава и известных шаблонов, не гарантия выявления любого возможного секрета.

`AGENTS.md`, четыре SVG, `STUDIO`, бизнес-модули доступности/выбора/демо-сервиса и `package-lock.json` сохранены без изменений. Ветки `main` и `feat/booking-ui-v1.1` не изменяются; слияний/force push нет. Бесплатность Pages зависит от Public-видимости. GitHub может журналировать технические запросы/IP на своей стороне; контакты приложение не отправляет.

Физические Mac/iPhone, Safari и Firefox отдельно не проверялись. Окончательные фотографии, адрес, номер администратора и маркетинговые тексты остаются предметом будущего согласования. Открытая вкладка хранит вымышленные контакты в оперативной памяти до сброса/перезагрузки/закрытия — это необходимо для итогового экрана. Правовое основание обработки реальных персональных данных не решено и до реального запуска обязательно к согласованию.

Архитектурный вывод: интерфейс и чистая логика переносимы на Node/VPS; нужно отдельно согласовать API/БД и затем реализовать серверную атомарную защиту от двойного бронирования. [Анализ VPS](../../deployment-architecture.md) содержит варианты без окончательного выбора backend/СУБД. Второй функциональный этап не начат; VPS, VPN, БД, уведомления и оплата не подключались.
