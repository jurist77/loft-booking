## Бесплатность и назначение

GitHub Free предоставляет Pages для **публичных** репозиториев. Видимость текущего репозитория из этой среды достоверно не установлена: API блокируется сетевой политикой, а анонимное открытие репозитория возвращает 404.
Не покупать тариф и не менять видимость автоматически. Если репозиторий Private, владелец должен отдельно решить, допустимо ли раскрыть весь код и историю. При необходимости сохранить код закрытым бесплатная публикация этого репозитория через Pages недоступна; требуется отдельное согласование альтернативы.

Pages используется только для согласования вымышленного интерфейсного прототипа: нет реальной аренды, платежей, базы, API, рассылок и приёма заказов. Согласно [ограничениям Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits), площадка не предназначена для работы онлайн-бизнеса, электронной коммерции или коммерческого SaaS. Перед реальным запуском перейти на собственный VPS. Условия/лимиты GitHub могут меняться; проверять их перед публикацией. [Доступность Pages по тарифам](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).

Четыре текущих изображения — локальные SVG-иллюстрации, созданные для этого проекта в предыдущем этапе, а не сторонние фотографии. Их файлы не заменены. Тексты и иллюстрации не загружаются из фотосервисов; внешние шрифты не подключаются. Для настоящих фотографий позже потребуется подтверждение прав заказчиком.

## Однократные действия владельца GitHub

1. Войти в GitHub и открыть [репозиторий](https://github.com/jurist77/loft-booking). Проверить видимость: для бесплатного сценария она должна быть Public. Если Private — остановиться и отдельно согласовать раскрытие кода; workflow сам этого не делает.
2. Открыть **Settings → Actions → General**. Разрешить GitHub Actions и используемые официальные действия `actions/*`; ограничения организации также должны их допускать. Не выдавать всем заданиям широкие права: нужные разрешения заданы в YAML.
3. Открыть **Settings → Pages → Build and deployment → Source → GitHub Actions**. Сохранить выбор. Не выбирать публикацию папки из ветки и не создавать `gh-pages`.
4. Если **Settings → Environments → github-pages** ограничивает ветки, разрешить `feat/booking-demo-deploy-v1.2`. При наличии обязательного подтверждения deployment выполнить его в интерфейсе GitHub. Защиту основной ветки не снимать.
5. После отправки ветки открыть [Actions](https://github.com/jurist77/loft-booking/actions), запуск **Deploy Loft Booking DEMO to Pages** именно для этой ветки. Если первый запуск упал до включения Pages, выбрать **Re-run all jobs**. Запускать deployment из другой ветки workflow не разрешает.
6. Дождаться успеха **build**, **deploy** и **verify-published**. Открыть HTTPS-адрес из deployment/summary. В артефакте **published-demo-verification** находятся снимки и JSON проверок именно публичного адреса; срок хранения — семь дней.

Кнопка **Run workflow** для `workflow_dispatch` обычно требует наличия workflow в default branch. Ради неё не сливать ветки: первоначальная отправка/следующий обычный коммит запускает `push`, а существующий запуск можно повторить через **Re-run all jobs**.

Для управления из облачной среды нужен доступ к `api.github.com`; для проверки сайта — к `jurist77.github.io`. На момент проверки Pages доступен и отвечает `404 Site not found`, а API блокируется прокси. Они добавлены в черновик настроек среды без удаления прежних разрешений. Сохранение черновика не применяет сеть к текущей машине автоматически: владелец должен сохранить изменения в настройках среды; затем доступ проверяется повторно. Токены в чат не передавать. Доступ native Git уже работает, но сам по себе не доказывает наличие административных прав Pages/API.

## Автоматическая публикация

[Workflow](../.github/workflows/demo-pages.yml) работает при push в `feat/booking-demo-deploy-v1.2` и сохраняет историю. Слияние в `main` не требуется.

Порядок: публичность → метаданные Pages → `npm ci` → тесты/типы/линтер → обычная Node-сборка → статический экспорт → E2E под базовым путём → аудит артефакта → официальные upload/deploy Pages → E2E реального сайта → восемь ширин и скриншоты. Официальные actions закреплены полными SHA. Build имеет `contents: read` и `pages: read`; deployment — только `pages: write` и `id-token: write`. Checkout не сохраняет Git-учётные данные.

Публикуется исключительно `out/`, не рабочая папка, `.next`, документация или тестовые данные. `.nojekyll` сохраняет каталоги `_next`. Неудачная сборка/тесты не запускают deployment. Ошибка проверки уже опубликованного адреса делает весь запуск неуспешным, но сама по себе не откатывает уже опубликованный артефакт: при необходимости отключить сайт или исправить и повторить публикацию.

## Обновление и отключение

Для обновления: внести согласованные изменения в эту ветку, выполнить обязательные проверки, создать обычный коммит и `git push origin feat/booking-demo-deploy-v1.2`. Проверить новый Actions run и публичный адрес. Force push не нужен. Для повтора без изменения кода использовать **Re-run all jobs**.

Для отключения: **Settings → Pages → Unpublish site** (название может зависеть от интерфейса GitHub); затем **Actions → Deploy Loft Booking DEMO to Pages → … → Disable workflow**, чтобы следующий push не опубликовал сайт снова. Коммиты и другие ветки сохраняются.

## Локальное воспроизведение и конфигурация

```bash
npm ci
npm test
npm run typecheck
npm run lint
npm run build
npm run build:demo
npm run audit:demo
npm run preview:demo
```

В другом терминале, только для внутренней проверки:

```bash
PLAYWRIGHT_BASE_URL=http://127.0.0.1:4173/loft-booking/ npm run test:e2e
ACCEPTANCE_BASE_URL=http://127.0.0.1:4173/loft-booking/ npm run verify:demo
ACCEPTANCE_BASE_URL=http://127.0.0.1:4173/loft-booking/ npm run capture:acceptance
```

Это локальная проверка экспорта; она не подтверждает работу GitHub Pages. `preview:demo` обслуживает только готовые файлы, не является backend. Нужен Chromium: в этой среде `/usr/bin/chromium`; на другой машине указать `CHROMIUM_PATH`. В Actions устанавливается браузер Playwright.

| Параметр | DEMO | Будущий VPS |
|---|---|---|
| `DEPLOY_TARGET` | `pages` задаётся `build:demo` | не задаётся для `npm run build` |
| `NEXT_PUBLIC_APP_MODE` | `demo` | `production` после реализации реального сервиса |
| `NEXT_PUBLIC_BASE_PATH` | путь из configure-pages, обычно `/loft-booking` | обычно пустой |
| `NEXT_PUBLIC_API_BASE_URL` | принудительно пустой | согласованный путь API, например `/api` |

Это публичные параметры сборки, не секреты. Переменные Next.js встраиваются при build; при изменении нужна пересборка. `NEXT_PUBLIC_APP_MODE=production` и адрес API сейчас только описывают будущую конфигурацию: они не включают реальное сохранение и не отключают демонстрационные предупреждения. Никакого скрытого production backend нет.

Для собственного домена/корневого размещения задать пустой `NEXT_PUBLIC_BASE_PATH` и при сборке, и при локальном обслуживании/аудите. Workflow получает путь из Pages автоматически. Не вшивать URL Pages в бизнес-логику. Не запускать dev и build одновременно: обе сборки Next.js используют `.next`; `out/` после экспорта независимо обслуживается статическим сервером.

## Маршруты и данные

Единственный клиентский маршрут — главная страница; переход к календарю — `#booking`, остальные секции — hash-ссылки. Форма и итог — состояние в памяти, без отдельных URL. Обновление страницы и прямое открытие `/loft-booking/#booking` работают; обновление очищает контакты и выбор. Назад/Вперёд работают для существующих hash-переходов, а не как история шагов формы. Неизвестные отдельные маршруты получают 404; фиктивный SPA fallback не нужен.

Календарь получает текущее время после открытия страницы, а не при статической сборке. Расчёты остаются в `Europe/Moscow`, окно +3 календарных месяца, рабочие часы и сетка не изменены.

Контакты удерживаются только в памяти вкладки до сброса/перезагрузки/закрытия. Форма не делает сетевых запросов и не пишет их в URL, localStorage, sessionStorage или cookies. Аналитики и внешних сборщиков данных нет. Использовать только вымышленные значения. GitHub как хостинг может обрабатывать технические запросы и IP-адреса по собственной политике; приложение не контролирует его инфраструктурные журналы. Это не готовый правовой режим обработки реальных персональных данных.
