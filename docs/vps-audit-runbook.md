# Аудит VPS 2.5.1: безопасный запуск владельцем

Это подготовка инструментов, **не выполненный аудит Швеции/Финляндии и не установка**. В облачной среде нет настроенных адресов/SSH-доступа к этим VPS; конфигурация среды не содержит VPN-доступа или учётных данных. Проверка на cloud/CI runner не является измерением VPS.

Основа: `main` после PR №10, `7d746f940b1e96f699a512e54e93438b85444c6f`. Исходная ветка и приложение сохранены. [Таблица фактов](vps-comparison-v2.5.1.md), [проект размещения](vps-deployment-plan.md), [проверки инструмента](acceptance/v2.5.1/README.md).

## Что делает скрипт

`scripts/vps-audit.py` требует только уже установленный Python 3.9+ и Linux `/proc`; Ubuntu 24.04 обычно содержит Python 3.12. Дополнительных Python/npm-пакетов нет. Если Python отсутствует, **ничего не устанавливать**: сообщить об этом для отдельного решения. Node нужен приложению в будущем, но не аудиту.

Скрипт читает числовые показатели `/proc`, список процессов (`comm`, `status`), `/etc/os-release`, статистику файловых систем фиксированных каталогов. Делает одну секундную выборку CPU, без нагрузки. Вызывает только фиксированные команды:

| Команда | Назначение / публикуемые данные |
| --- | --- |
| `systemctl list-units --type=service --state=running/failed …` | Число служб каждой известной категории; неизвестные — `other`, описания удалены |
| `systemctl list-unit-files --type=service …` | Признаки установленных, в том числе неактивных служб; названия неизвестных скрыты |
| `systemctl is-system-running` | Только состояние, например `running` или `degraded` |
| `ss -H -lntup` | Только слушающие TCP/UDP-порты, область привязки, категория владельца; без адресов/PID |
| `ufw status` | Только active/inactive, без правил |
| `nft list tables` | Только число таблиц, без имён и правил |
| `iptables -S`, `ip6tables -S` | Только стандартные default policies и число правил; строки/адреса/комментарии удалены |
| `node --version` | Только проверенный номер версии |

Исполняемые файлы ищутся в стандартных `/usr/local/{sbin,bin}`, `/usr/{sbin,bin}`, `/sbin`, `/bin`, не в пользовательских каталогах. Node из nvm может быть не обнаружен: владелец отдельно сообщает его версию и способ установки, без env/конфигураций. Для каждой команды тайм-аут 8 секунд. Системные команды выполняются последовательно; при зависании всех инструментов отчёт может готовиться около 90 секунд.

Нет сетевых запросов, чтения argv/environ, журналов, содержимого VPN/proxy-конфигураций, сертификатов/ключей, установок, записей в файлы или управления службами. Вывод — только JSON в stdout. SSH/sudo могут штатно регистрировать сам факт входа/запуска в системном журнале.

`missing` = инструмент отсутствует; `unavailable` = отказ команды/прав/системной службы; `timeout` = превышен лимит; `null` = показатель недоступен. Это **не означает отсутствие VPN/firewall/OOM**. Exit 0 означает, что базовые показатели RAM/uptime прочитаны; дополнительные неизвестные всё равно требуют уточнения. Exit 2 — нет основных данных/ошибка чтения. Неизвестные имена служб и процессов намеренно скрыты. Переименованный VPN, контейнер, WireGuard в ядре могут не распознаться.

## Запуск с Mac без копирования файлов на VPS

Используйте уже работающий SSH-доступ и проверенные ключи серверов. В примерах `sweden-vps` и `finland-vps` — **локальные SSH-алиасы владельца**, их нужно заменить своими. Это не реальные адреса. Не отключать проверку host key и не пересылать пароли/ключи в чат.

1. На Mac в существующем checkout получите ветку и извлеките скрипт. Рабочие файлы проекта не переключаются:

```bash
git fetch origin feat/vps-deployment-audit-v2.5.1
umask 077
mkdir -p /tmp/studio-vps-audit
git show origin/feat/vps-deployment-audit-v2.5.1:scripts/vps-audit.py > /tmp/studio-vps-audit/vps-audit.py
shasum -a 256 /tmp/studio-vps-audit/vps-audit.py
less /tmp/studio-vps-audit/vps-audit.py
```

2. Проверьте содержимое и SHA относительно согласованного PR/коммита. Не выполнять скачанный изменяемый URL через `curl | sudo`. Сначала запустите **без повышения прав**:

```bash
ssh -T sweden-vps 'PYTHONDONTWRITEBYTECODE=1 python3 - --label sweden' < /tmp/studio-vps-audit/vps-audit.py > /tmp/studio-vps-audit/sweden.json
ssh -T finland-vps 'PYTHONDONTWRITEBYTECODE=1 python3 - --label finland' < /tmp/studio-vps-audit/vps-audit.py > /tmp/studio-vps-audit/finland.json
```

Необязательная предварительная проверка наличия Python: `ssh -T sweden-vps 'command -v python3'`. Если SSH завершается с ошибкой или Python отсутствует, отчёт не получен. Не публиковать stderr SSH: он может содержать адрес/имя пользователя. Не повторять с отключённой проверкой host key.

3. Если сведения о firewall/владельцах портов недоступны и у текущей учётной записи **уже есть** право sudo, после проверки скрипта допустим такой read-only запуск (никаких прав/паролей не настраивать):

```bash
ssh -T sweden-vps 'sudo -n /usr/bin/python3 - --label sweden' < /tmp/studio-vps-audit/vps-audit.py > /tmp/studio-vps-audit/sweden-privileged.json
ssh -T finland-vps 'sudo -n /usr/bin/python3 - --label finland' < /tmp/studio-vps-audit/vps-audit.py > /tmp/studio-vps-audit/finland-privileged.json
```

`sudo -n` не спрашивает пароль и не меняет sudoers; если нет разрешения, остановиться. Обычный отчёт остаётся полезным. При невозможности безпарольного sudo владелец может самостоятельно запустить проверенный файл в своей существующей защищённой сессии; не выдавать новые привилегии для аудита.

4. Просмотрите JSON на Mac, например `python3 -m json.tool /tmp/studio-vps-audit/sweden.json` (если Python на Mac уже установлен) или текстовым редактором. Баннер SSH в stdout делает файл невалидным — это не успешный результат.

5. Повторите в обычный и известный владельцу загруженный период, с разными именами выходных файлов, например `sweden-evening.json`. Не создавайте нагрузку на VPN. Желательно несколько снимков в течение нескольких типичных рабочих дней и существующая история панели провайдера за 7–14 дней. Скрипт не устанавливает сборщик метрик и не восстанавливает прошлые пики из одного снимка.

## Безопасная передача результатов

Передайте обезличенные JSON **приватным вложением**, отдельно подписав страну и «обычный/загруженный период». Не добавлять реальные отчёты в публичный репозиторий, issue или PR. Даже номера портов и версии — инфраструктурные сведения, поэтому владелец должен проверить файлы перед отправкой. Сохранить числовые значения, статусы missing/unavailable и время измерения; не подменять их оценками.

Отдельно нужны короткие ответы без секретов:

- Какие категории VPN реально используются, в том числе если скрипт показал `other`? Есть ли контейнеры/нестандартные имена? Только назначение службы, без клиентских ID и конфигов.
- Кто занимает 80/443, где завершается TLS, как обновляется сертификат? Для reverse proxy достаточно схемы маршрутизации с заменёнными адресами/именами, **не полного конфига**.
- Есть ли внешний firewall провайдера и разрешён ли существующий SSH-доступ? Не присылать токены/правила с IP клиентов.
- Известны ли пиковые CPU/RAM/трафик VPN, OOM/сбои за последние недели, допустимое окно работ?
- Какие уже имеющиеся бесплатные варианты защищённого адреса/резервного носителя доступны? Нужен тестовый доступ с Mac и телефона.

Не присылать `.env`, private keys, базу SQLite, дампы, подписки/ссылки VPN, конфигурации 3X-UI/Xray, необработанные `ps aux`, `journalctl`, `systemctl status`, `ss -p`, firewall или сертификаты. Скрипт такие исходные данные не выводит.

После получения обоих наборов заполнить таблицу, оценить запас и отдельно согласовать сервер/сеть/изменения. До этого завершается **только подготовка инструментов аудита**.
